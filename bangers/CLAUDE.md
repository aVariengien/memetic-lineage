## Project Overview

Bangers is a Next.js 16 application displaying the most-quoted tweets from the Community Archive (a crowdsourced Twitter history database). Users browse top tweets by year and explore quote tweets, threads, and semantic search results through a stacked pane navigation interface.

## Commands

```bash
pnpm dev          # Start development server
pnpm build        # Production build
pnpm lint         # Run ESLint
pnpm test         # Run tests with Vitest
```

## Architecture

### Data Sources (Local-First)

The website runs on **local JSON files** without requiring external databases. All data is pre-generated and served from the `public/` directory.

**Primary data files:**
- `public/bangers_tweets.json` (~16 MB) - All tweets indexed by ID with year sorting, quote relationships, and conversations
- `public/strands_data.json` (2.2 MB) - 252 strands with seed tweets
- `public/atlas_data.json` (14.3 MB) - UMAP visualization data for strand atlas

**Data generation scripts (in `scratchpads/`):**
- `23_generate_bangers_data.py` - Generates `bangers_tweets.json` from atlas, strand data, and Community Archive Supabase
- `22_generate_atlas_data.py` - Generates `atlas_data.json` for visualization
- `strands.py` - Core strand processing pipeline
- `lib/strand_caches.py` - Generates diskcache indexes (tweet_dict, reply_trees, quote_tweets) from enriched_tweets.parquet
- `lib/count_quotes.py` - Computes quote counts excluding self-quotes

**Runtime data from Community Archive Supabase:**
- Avatars: Fetched at runtime via `app/actions/avatars.ts` from `all_account` JOIN `all_profile`
- The CA Supabase also has `public.quote_tweets` table (1.2M+ rows) with `(tweet_id, quoted_tweet_id)` - the authoritative source of quote relationships

### Core UI Pattern: Stacked Panes

The main interaction uses horizontally stacked panes with collapsible "spine" navigation:
- Home view shows tweets grouped by columns (years)
- Clicking a tweet opens a `TweetPane` to the right
- Additional clicks stack more panes; inactive panes collapse to `VerticalSpine` components
- URL syncs the selected tweet stack via `useUrlSync` hook

### Key Components

- `HomePageClient`: Main client component with pane stacking, uses hooks from `app/hooks/`
- `TweetPane`: Detail view with tabs for quotes, thread, and vector search
- `TweetCard`: Renders tweets with media and quoted tweet support
- `VerticalSpine`: Collapsed pane showing rotated text for navigation

### Custom Hooks (`app/hooks/`)

- `useTweetSelection`: Manages selected tweet stack state
- `useUrlSync`: Bidirectional URL sync for tweet selection
- `usePaneNavigation`: Scroll container and pane width calculations
- `useAvatar` / `prefetchAvatars`: Fetch avatar URLs from Community Archive Supabase with batching, deduplication, and client-side caching

### Data Fetching (`lib/api.ts`)

Uses local data from `lib/localData.ts`:
- `fetchTweetDetails`: Lookup tweets from `bangers_tweets.json`
- `getThread`: Get conversation tweets from local data
- `getQuotes`: Get quote relationships from local data
- All functions use in-memory caching with 5-minute TTL

### Strands Feature (`app/best-strands/`)

Displays curated "strands" loaded from JSON files. Each strand has a seed tweet, rating scores, and essential tweets list.

## Types (`lib/types.ts`)

Key interfaces: `Tweet`, `Strand`, `StrandWithTweet`, `StrandRating`

## Data Generation

### Regenerate All Data

Everything is generated by the unified pipeline in `scratchpads/strands.py`:

```bash
cd scratchpads

# Full pipeline (strands + atlas + bangers)
uv run python strands.py

# Only regenerate bangers_tweets.json (Phase 8, fastest)
uv run python strands.py --bangers-only

# Custom parquet path
uv run python strands.py --bangers-only --parquet /path/to/tweets.parquet

# Then restart dev server with clean cache
cd ../bangers && rm -rf .next && pnpm dev
```

**Deprecated:** `23_generate_bangers_data.py` (replaced by Phase 8 in strands.py, does not filter self-quotes)

### bangers_tweets.json Structure

```typescript
interface BangersData {
  generatedAt: string;
  tweetCount: number;
  tweets: Record<string, TweetRecord>;       // tweet_id -> tweet data
  byYear: Record<string, string[]>;          // year -> tweet_ids sorted by score
  quoteRelationships: {
    quotesOf: Record<string, string[]>;      // original -> quoting tweets
    quotedBy: Record<string, string>;        // quote -> original tweet
  };
  conversations: Record<string, string[]>;   // conversation_id -> tweet_ids
  tweetToConversation: Record<string, string>; // tweet_id -> conversation_id
  replies: Record<string, string>;           // tweet_id -> parent_tweet_id
}
```

## Known Issues / TODO

### Quote Count Pipeline - FIXED (Feb 27)

**Was:** `archive_quote_count` didn't filter self-quotes, inflating counts (e.g. mr_samosaman showed 84 but 84/85 were self-quotes). `quotesOf` was only populated for 252 strand roots.

**Fix:** Phase 8 in `strands.py` now uses `lib/count_quotes.py` which properly filters self-quotes via account_id comparison. Quote relationships are built from the parquet's `quoted_tweet_id` column (or `filtered_quote_tweets.diskcache`) for ALL tweets, not just strand roots.

**Pipeline:**
```
ca_jan_2026.parquet (10M+ tweets, source of truth)
  → lib/count_quotes.py::count_quotes(df, valid_account_ids)
    → archive_quote_count (self-quote filtered, archive users only)
    → quote_count (self-quote filtered, all users)
  → lib/strand_caches.py::generate_filtered_quote_cache()
    → filtered_quote_tweets.diskcache (quoted_id → [quoting_ids], no self-quotes)
  → strands.py Phase 8 (--bangers-only)
    → Merges atlas + strands + thread_text + parquet enrichment
    → Builds quotesOf/quotedBy from filtered diskcache (or parquet fallback)
    → Adds quoting tweets to dataset for TweetPane display
    → Output: bangers_tweets.json
```

**Community Archive schema reference:**
```sql
CREATE TABLE public.quote_tweets (tweet_id TEXT, quoted_tweet_id TEXT, PRIMARY KEY (tweet_id, quoted_tweet_id));
CREATE TABLE public.all_account (account_id TEXT, username TEXT, ...);
CREATE TABLE public.all_profile (account_id TEXT, avatar_media_url TEXT, ...);
CREATE TABLE public.tweets (tweet_id TEXT, account_id TEXT, full_text TEXT, ...);
```

## Future: Real-time Supabase Integration

Currently the website uses local JSON files. To enable real-time Supabase integration:

### 1. Set Environment Variables

Create `.env.local` with:
```
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_KEY=your-anon-key
NEXT_PUBLIC_CA_SUPABASE_URL=https://community-archive.supabase.co
NEXT_PUBLIC_CA_SUPABASE_KEY=community-archive-anon-key
```

### 2. Database Schema (Top QT)

```sql
create table public.community_archive_tweets (
  tweet_id text primary key,
  created_at timestamptz not null,
  full_text text,
  username text,
  favorite_count int default 0,
  retweet_count int default 0,
  quote_count int default 0,
  year int,
  quoted_tweet_id text,
  avatar_media_url text,
  conversation_id text,
  media_urls text[]
);

create index tweets_quote_count_idx on public.community_archive_tweets (quote_count desc);
create index tweets_year_idx on public.community_archive_tweets (year);
```

### 3. Create Hybrid Data Source

Create `lib/dataSource.ts` for environment-based switching:
```typescript
const USE_LOCAL = !process.env.NEXT_PUBLIC_SUPABASE_URL ||
                  process.env.USE_LOCAL_DATA === 'true';

export const fetchTweets = USE_LOCAL
  ? fetchFromLocal
  : fetchFromSupabase;
```

### 4. Strands Real-time

To make strands real-time:
1. Create `strands` table in Supabase with columns from `StrandWithTweet` interface
2. Create `strand_tweets` junction table for essential tweets
3. Create migration script to upload `rated_strands/*.json` to database
4. Update `best-strands/page.tsx` to query Supabase

### 5. Incremental Sync

For periodic updates:
1. Add `last_updated` timestamp to `bangers_tweets.json`
2. Create sync script to fetch new tweets from Supabase since last update
3. Run on cron or manual trigger: `uv run python sync_bangers_data.py`
